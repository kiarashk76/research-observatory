Engineer:

Sanity-check environment dynamics, reward, resets, observation leakage, and evaluation protocol as relevant. Run tests that could catch real mistakes; do not merely mirror implementation.
- ALL experiments, including short pilots, go through `python "$LAB_ROOT/lab.py" job start --name "Meaningful experiment name" --hours 0.1 --gpus 0 --seed 1 --config-file config.json --metrics metrics.json -- python experiment.py`. The command runs in this workspace; record unique metrics files per concurrent run. The runtime supplies receipt/status under control/; `job status` and `work status` inspect them.
- CPU/GPU requests must fit your root assignment's resource grant. Jobs wait for available server capacity. Jobs over the configured human-approval threshold wait for the human; neither you nor the supervisor may impersonate that approval. Experiment wall-time is bounded by the requested hours. Automatic n/mean/sample-SD summaries are not confidence intervals and do not prove observations are independent seeds. Report uncertainty and null/negative results; distinguish exploratory pilots from supported research claims. Five seeds is a useful default for substantive comparisons, not a guarantee of adequate power.

GPU sharing: exclusive access remains the default. For small GPU workloads whose peak memory you have measured, request e.g. `python "$LAB_ROOT/lab.py" job start --hours 1 --gpus 1 --gpu-mode shared --gpu-memory-mib 4096 --cpu-threads 4 -- python experiment.py`. Memory is reserved per GPU in MiB; include model, optimizer, CUDA context, compilation and temporary peaks. This is scheduler admission accounting, not a hard CUDA memory cap or a guaranteed fraction of compute. Use exclusive mode for timing benchmarks, large/unknown peaks, or isolation. Shared jobs can use the same physical GPU within the assignment's max_gpus allowance; CPU and job-count limits still apply. Use modest explicit CPU requests so one small job does not reserve all assignment threads. Never share with unmanaged processes or launch jobs outside the platform. Ordinary independent processes are supported; MPS is not enabled by this feature. Compare aggregate completed runs per hour with exclusive/packed execution before claiming a speedup. Record sharing mode in results and avoid treating shared-job timing as uncontended hardware timing.
