# Research Notes

Each project has multiple named human-owned notebooks in the dashboard's Research notes tab. The document editor supports H1/H2/H3 headings, bold/italic text, bulleted and numbered lists, boxed paragraphs, tables, PNG/JPEG figures, and rendered inline/display LaTeX equations. Click an equation to edit its LaTeX with a preview. Paste/import accepts Markdown and the `\( ... \)` / `\[ ... \]` math delimiters used by ChatGPT. Equations are rendered math, not arbitrary executable LaTeX programs. Reading preview hides editing controls; Download PDF exports the saved revision with equations and figures. Save explicitly with the button or Ctrl/Cmd+S. Copy all as Markdown copies the complete current editor contents, including unsaved edits, blockquotes/boxes, tables, headings, lists and LaTeX equation source. Paste it into ChatGPT or another editor. Figure references are included; clipboard text does not embed the image files. If clipboard access is blocked, a dialog selects the full source for manual Ctrl/Cmd+C. Copy document reference remains a separate button for asking agents to read the notes.

The compact icon toolbar stays visible while you scroll; hover a button for its name. Enter full screen expands the writing surface and hides the side panel. Use the panel icon to reopen sections, agent suggestions or history. Exit with the full-screen button or Escape; Escape closes an open equation/review dialog first. Full-screen mode preserves the editor and unsaved draft.

Click inside a table, quote, paragraph, figure or equation, then use Select block to highlight the complete outer document block. Move up and Move down change its position; Delete block removes it. Undo restores the change. Table controls also add/delete individual rows and columns, or delete the table. Align left, Align center and Align right apply to the current block or blocks covered by a text selection; alignment persists in saved notes, reading previews and PDFs. Layout is saved using restricted `:::notes-align left|center|right` / `:::end-notes-align` Markdown containers rather than executable HTML. Agents should preserve these containers when proposing edits.

Saving, exporting, restoring, granting permission, and accepting/rejecting suggestions never enqueue model work. Ask the supervisor in Slack to read a named section or paste a copied reference. The reference identifies the project, revision and section; copying it does not contact an agent. Agents receive lightweight note metadata, not the whole document on every wake. Readable saved content is projected to the project's `notes/research-notes/<note_id>.md`; the default note also retains `notes/research-notes.md` for existing references and figures under `notes/research-notes-assets/`.

Agent comments and proposed changes appear in the sidebar. Review a proposal's source version and suggested text/figure, then accept or reject. Ordinary proposals do not edit the original. A stale proposal cannot overwrite a newer revision. Request an updated proposal when necessary.

For explicitly authorized direct edits, select a scope and click Allow one agent edit, then copy its permission reference into Slack with your instruction. Alternatively, type `!notes allow Section title` or `!notes allow all` in the project's Slack channel. That command creates a permission without waking a model; ask the supervisor to use it when ready. Permissions are single-use, project- and note-scoped and tied to a document revision. They can be revoked, and become stale when another revision is saved. Only the supervisor can consume a direct-edit permission; specialists may submit proposals or comments.

Agents use `propose_research_notes` and, for an authorized supervisor edit, `edit_research_notes` with `grant_id`. `notes_change` includes `note_id`, `base_revision`, `mode` (`replace`, `append`, `comment`), `section` (copied key/title or empty for the whole document), `replacement`, `comment`, `summary` and optional `figure_paths`. Section replacements must preserve their heading and cannot introduce headings that escape the selected scope. PNG/JPEG figures from the project or the session's workspace are validated and staged as part of a proposal.

Canonical source and history live in the platform database, outside agent write permissions. Generic write_note actions cannot overwrite their generated projections. Mutating notes HTTP routes require dashboard credentials even on localhost; the public Caddy password proxy forwards Authorization only to the local backend. Agents' sandbox cannot read those credentials. Existing origin checks and the Caddy cross-site checks remain in force. Image inputs are bounded and verified; SVG and external images are not loaded. Notes rendering does not execute raw HTML or trusted TeX commands.

Optimistic revision checks reject concurrent saves without replacing the editor contents. An unsaved recovery draft is kept in that browser's local storage, and the UI warns before leaving. Download my draft provides an independent Markdown copy. Compare/load the latest saved copy to resolve conflicts; the system does not silently merge competing edits. Version history can restore an older document as a new revision while retaining previous saved versions.

The editor, fonts and math renderer are bundled as local static assets. `frontend/research-notes/package-lock.json` pins dependencies. Build with the workspace Node binary and `node frontend/research-notes/build.mjs` after installing dependencies with npm. Headless Chromium under `runtime/tools/playwright` performs bounded CPU-only PDF exports with network requests blocked except local bundled assets. No API keys, external editing service or model call is used. Browser integration tests exercise the user's full math example, uploads, PDFs, proposal acceptance, revision restore, scoped permissions, conflicts, draft recovery and executable-content rejection.

Copy section as Markdown opens a heading picker using the current draft, including unsaved edits. Choose an H1, H2 or H3; the copy includes that heading and ends before the next heading of the same level (or at document end). Intervening headings of other levels are included. Equations, tables, boxes and balanced alignment containers are preserved. The source preview also supports manual copying if clipboard access is denied. Copying does not save notes or wake agents.

Two columns places the current block in the left side of a local two-column layout, with an empty right side ready to edit. Tables, quotes, equations, figures and text can be placed in either side. Move to other column transfers the current block; normal block selection/move/delete/alignment controls operate within the selected column. Remove columns preserves both sides in left-then-right reading order. Undo restores layout edits. Columns stack on narrow screens and remain side by side in PDF exports. Copy all preserves the layout using restricted `:::notes-columns` / `:::notes-column` containers. Copy section flattens column layout into normal Markdown so a partial row remains readable. Saving and layout editing do not wake agents.

Click inside either column to show the Columns width slider in the toolbar. It controls the left column from 20% to 80%; the right column uses the remainder. Each two-column block remembers its own ratio through saves, block transfers, previews and PDF exports. Unequal layouts use an optional left-width suffix, for example `:::notes-columns 35` for 35/65. Older layouts without a suffix remain 50/50.

The Size menu changes selected text or the next text typed. Default removes the explicit size; 12–48 px options support paragraphs, headings, lists and table text. Font sizes persist in restricted `<span data-notes-font-size="24">…</span>` Markdown annotations, rendered locally without allowing arbitrary HTML or CSS. Copy all/section retain these annotations. Both controls support Undo and do not wake agents.

Underline is available beside Bold and Italic, or with Ctrl/Cmd+U. It applies to selected text or the next text typed, toggles off with the same control, and survives save/reload, Markdown copying, reading preview and PDF export. Markdown uses `<u>…</u>` because underscores in ordinary Markdown represent emphasis. Only exact underline tags are accepted by the renderer; arbitrary HTML stays disabled.

Pending edits are checked against the exact original source of their target section, not just the document revision. An older proposal can be accepted if that section (including its heading, subsections and whitespace) is unchanged. Changes elsewhere and accepting a different section do not invalidate it. A changed, renamed or removed target stays blocked with a visible explanation. Whole-document proposals require the entire source to match. Acceptance rechecks the latest saved revision and target atomically, preserves other sections and still requires a human click. Unsaved drafts must be saved or resolved first; one-time agent edit grants retain their existing current-revision checks.

Full-screen Notes starts with a compact single-row toolbar containing Save, reading preview, Show writing tools and Exit full screen, plus the saved/unsaved status. Show writing tools expands the formatting controls and other document actions; Hide writing tools collapses them again. The compact row stays reachable while scrolling. Exiting full screen restores the normal toolbar. Layout changes preserve the draft and do not save or wake agents.

Use the Note selector to switch documents, New note to create a named document, and Rename to change its title. IDs and readable paths stay stable across renames. Each note has its own saved revisions, pending suggestions, grants and browser recovery draft. Switching notes preserves an unsaved draft; reopening restores it. The last selected note is remembered per project. Existing notebooks, revision history, proposals, grants and assets remain attached to the default Research Notes document without rewriting their records.

Agents receive a lightweight documents list and must include `note_id` in their notes changes when a project has multiple notes. Research Chat exposes each note as separate searchable evidence and links suggestions to that note. Discuss with Claude carries the selected note ID; including its unsaved draft remains optional. Slack supports `!notes allow NOTE_ID | SECTION` or `!notes allow Note title | all`. Use an ID when titles are duplicated. The old `!notes allow SECTION` form remains available for single-note projects; projects with multiple notes require an explicit target. Generic agent writes cannot replace note projections.

The note selector and New note, Rename, Archive or delete note, and Archived notes icons share the compact document toolbar. Hover an icon for its label. Font-size controls have the same height as other toolbar controls.

Removing a note archives it if its current editor contents, saved source, or any saved revision contain non-whitespace content. Unsaved editor contents are saved atomically before archiving. Archived notes retain their text, figures, history and pending proposals, appear under Archived notes, and can be viewed or restored. Active one-time agent edit permissions are revoked; restoring never reactivates them. Archived notes are excluded from active agent/chat evidence and readable projections. Earlier removed notes whose saved content was retained are also available as archives.

Truly empty notes are permanently removed, including empty revision/proposal/permission records; a minimal identity tombstone prevents stale clients from recreating them. Removing the last active note creates a fresh blank Research Notes document. Confirmation explains whether the note will be archived or permanently deleted. These actions do not wake agents.
